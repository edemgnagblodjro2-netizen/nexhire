**Bloc 111 — Chatbot flottant freemium (essai 3 jours × 15 questions/jour, puis paywall Premium)** :

- **Nouvelle table DB `ai_trials`** (`lib/db/src/schema/aiTrials.ts`) : `client_key varchar(128) PK` + `started_at timestamptz NOT NULL DEFAULT now()`. Index sur `started_at`. Persiste la date du premier message envoyé via le canal flottant pour chaque "client" (préfixe `u:` + userId pour les connectés, `ip:` + IP pour les anonymes) → résiste aux redémarrages serveur (sinon l'essai redeviendrait infini). Schéma exporté depuis `@workspace/db`. Table créée via psql (drizzle-kit symlink cassé dans ce repl, fallback `CREATE TABLE IF NOT EXISTS` direct).
- **Server `routes/ai.ts`** : (1) Constantes `FLOATING_DAILY_LIMIT = 15` + `FLOATING_TRIAL_DAYS = 3`. (2) Helper `getOrCreateTrialStart(clientKey)` : upsert atomique sur `ai_trials` qui retourne le `started_at` existant ou nouvellement créé (fail-open en cas d'erreur DB pour ne pas bloquer tout le monde sur un hiccup). (3) Helper `daysSince(start)` : retourne le nombre de jours entiers UTC écoulés. (4) Dans le route handler quota, **avant** le compteur quotidien : `if (isFloating)` → récupère/crée `trialStart`, si `daysSince(trialStart) >= 3` retourne 429 avec `{trialExpired:true, trialDays:3, upgradeUrl:"/premium", error:"Votre essai gratuit de 3 jours de l'assistant IA est terminé. Passez à Premium pour continuer à discuter."}` (FR/EN). (5) Sinon applique la limite quotidienne 15/jour standard avec message "Vous avez utilisé vos 15 questions gratuites pour aujourd'hui. Réessayez demain ou passez à Premium pour un accès illimité."

- **Client `FloatingAIChat.tsx`** : Type `Msg` étendu avec `isQuotaExceeded?: boolean`. Sur 429+`quotaExceeded` (couvre à la fois trialExpired et limite jour), affiche le message d'erreur serveur + bouton « ⭐ Passer à Premium » → navigue vers `/premium`.

Privacy floor `MIN_AGGREGATE=5` clamps every aggregate (totals, daily series, top lists) below 5 events to zero. Visitor metric is split into `distinctAuthenticatedUsers` (count distinct user_id NOT NULL) and `anonymousEvents` (rows with NULL user_id) — never inflated estimates. Composite index `service_views(service_id, created_at)` and `services(city, active)` added for query performance.
